# დომინოს სტატისტიკა — Cursor-ის ეტაპობრივი პრომპტები

თითო ეტაპი ცალკე მიეცი Cursor-ს. შემდეგზე მხოლოდ მაშინ გადადი, როცა წინა მუშაობს და შემოწმებულია.
ბაზა უკვე მზადაა: `schema.sql` Supabase-ის SQL Editor-ში გაუშვი პირველ ეტაპამდე.

---

## ეტაპი 0 — პროექტის საფუძველი

```
შექმენი React + Vite პროექტი (JavaScript) სახელით domino-stats.
- დააინსტალირე @supabase/supabase-js და react-router-dom.
- src/lib/supabase.js-ში შექმენი Supabase client, რომელიც VITE_SUPABASE_URL და VITE_SUPABASE_ANON_KEY ცვლადებს .env-დან იღებს. დაამატე .env.example და .env ჩასვი .gitignore-ში.
- გამოიყენე HashRouter, რადგან საიტი GitHub Pages-ზე იქნება.
- vite.config.js-ში base დააყენე '/domino-stats/'.
- დაამატე GitHub Actions workflow (.github/workflows/deploy.yml), რომელიც main-ზე push-ისას ააწყობს და GitHub Pages-ზე ატვირთავს. Supabase-ის ცვლადები repository secrets-იდან წაიკითხოს.
- მთელი ინტერფეისი ქართულად. დიზაინი mobile-first: მთავარი გამოყენება ტელეფონიდან იქნება.
- ქვედა ნავიგაცია ტელეფონზე: „ჩაწერა“, „ცხრილი“, „წყვილები“, „პარტიები“, „მეტი“.
- გვერდები ჯერ ცარიელი placeholder-ები იყოს.
```

## ეტაპი 1 — ავტორიზაცია და უფლებები

```
ბაზაში არის ცხრილი app_roles (user_id, role: 'admin' | 'editor') და ფუნქციები is_editor(), is_admin().
საიტის კითხვა ყველას შეუძლია ავტორიზაციის გარეშე. ჩაწერა მხოლოდ editor-ს და admin-ს.
- გააკეთე შესვლის გვერდი email magic link-ით (supabase.auth.signInWithOtp). emailRedirectTo იყოს საიტის მისამართი.
- შექმენი AuthContext: session, user, role (app_roles-იდან წაკითხული ან null), signOut.
- „ჩაწერა“ და რედაქტირების ღილაკები გამოჩნდეს მხოლოდ editor/admin-ისთვის. სხვებს „ჩაწერა“ ტაბზე შესვლის შეთავაზება აჩვენე.
- „მეტი“ გვერდზე აჩვენე ვინ არის შესული და მისი როლი, და გამოსვლის ღილაკი.
```

## ეტაპი 2 — მოთამაშეების მართვა

```
ცხრილი players: id, name (unique), nickname, is_active.
- „მეტი“ გვერდზე დაამატე „მოთამაშეები“: სია, დამატება, სახელის შეცვლა, აქტიური/არააქტიური.
- დამატება და შეცვლა მხოლოდ admin-ს შეუძლია (RLS ამას ბაზაშიც ამოწმებს).
- მოთამაშე არ იშლება. არააქტიური მოთამაშე სტატისტიკაში რჩება, მაგრამ ჩაწერის ფორმაში აღარ ჩანს.
```

## ეტაპი 3 — პარტიის ჩაწერა (მთავარი ეკრანი)

```
ცხრილი matches: played_at, a1, a2 (გუნდი A), b1, b2 (გუნდი B), winner ('A'|'B'), win_type ('regular'|'sukhoi'|'koksi'), note, is_void.
points ბაზა თვითონ ითვლის (კოქსი 3, სუხოი 2, ჩვეულებრივი 1). წყვილის თანმიმდევრობას ბაზა თვითონ ალაგებს.

გააკეთე „ჩაწერა“ გვერდი, რომელიც ტელეფონზე 10 წამში ივსება:
- ორი ბლოკი: „გუნდი A“ და „გუნდი B“. თითოში 2 მოთამაშე აქტიური მოთამაშეების დიდი ღილაკებით (chip-ებით). ერთი მოთამაშე ორ ადგილას ვერ აირჩევა.
- „ვინ მოიგო?“ — ორი დიდი ღილაკი, რომლებზეც მოთამაშეების სახელები წერია.
- მოგების ტიპი — სამი ღილაკი: „ჩვეულებრივი (1)“, „სუხოი (2)“, „კოქსი (3)“. ნაგულისხმევად „ჩვეულებრივი“. ქვემოთ პატარა მინიშნება: სუხოი — წაგებულმა 200-ს ვერ მიაღწია, კოქსი — 100-ს ვერ მიაღწია.
- არასავალდებულო შენიშვნის ველი.
- „შენახვა“ ღილაკი. შენახვის შემდეგ ფორმაში იგივე 4 მოთამაშე დარჩეს (ხშირად იგივე შემადგენლობა აგრძელებს), გამარჯვებული და ტიპი გასუფთავდეს.
- ეკრანის ქვემოთ აჩვენე დღევანდელი პარტიების მოკლე სია და ამ შემადგენლობის დღევანდელი ანგარიში (მაგ. „A 4 : 2 B“).
- „ბოლო შემადგენლობის გამეორება“ და „გუნდების გადაცვლა“ ღილაკები.
```

## ეტაპი 4 — პარტიების სია და შესწორება

```
გვერდი „პარტიები“:
- ყველა პარტია თარიღის მიხედვით, უახლესი ზემოთ, დღეებად დაჯგუფებული.
- თითო სტრიქონი: გამარჯვებული წყვილი მწვანედ, წაგებული ნაცრისფრად, მოგების ტიპის ნიშანი (სუხოი / კოქსი).
- ფილტრები: პერიოდი, მოთამაშე.
- editor/admin-ს შეუძლია პარტიის შეცვლა და „გაუქმება“ (is_void = true). გაუქმებული პარტია ჩანდეს გადახაზული და სტატისტიკაში არ ითვლებოდეს. „აღდგენაც“ იყოს.
- პარტიის დეტალებში editor-ისთვის აჩვენე ცვლილებების ისტორია match_audit ცხრილიდან.
- გვერდებად დაყოფა (pagination) ან „მეტის ჩატვირთვა“.
```

## ეტაპი 5 — მთავარი ცხრილი (ინდივიდუალური)

```
ბაზაში არის RPC ფუნქცია player_stats(p_from timestamptz, p_to timestamptz). null ნიშნავს მთელ დროს.
აბრუნებს: player_id, name, games, wins, losses, win_pct, points_won, points_lost, net_points, koksi_made, koksi_taken, sukhoi_made, sukhoi_taken.

გვერდი „ცხრილი“:
- პერიოდის არჩევა: „დღეს“, „ეს კვირა“, „ეს თვე“, „წელი“, „მთელი დრო“, „სხვა პერიოდი“ (თარიღიდან თარიღამდე). პერიოდი ჩაიწეროს URL-ში, რომ ბმული გაზიარდეს.
- ცხრილი: ადგილი, მოთამაშე, თ (თამაშები), მ (მოგება), წ (წაგება), %, ქულები, კოქსი +/-, სუხოი +/-.
- სვეტებზე დაჭერით დალაგება.
- „მინიმუმ N თამაში“ ფილტრი (ნაგულისხმევად 5). ნაკლები თამაშის მქონე მოთამაშეები ცალკე, ქვემოთ ჩანდეს.
- ტელეფონზე ცხრილი კომპაქტური იყოს: მოთამაშე, ქულები, %, დანარჩენი სტრიქონზე დაჭერით გაიშალოს.
- მოთამაშის სახელზე დაჭერით მისი პროფილი გაიხსნას (შემდეგი ეტაპი).
```

## ეტაპი 6 — წყვილები და სუხოი/კოქსი

```
RPC ფუნქცია pair_stats(p_from, p_to) აბრუნებს: p1, p2, p1_name, p2_name, games, wins, losses, win_pct, points_won, points_lost, net_points, koksi_made, koksi_taken, sukhoi_made, sukhoi_taken.

1) გვერდი „წყვილები“: იგივე პერიოდის ფილტრი და დიზაინი, რაც „ცხრილს“ აქვს, ოღონდ წყვილებით. მინიმუმ თამაშების ფილტრი ნაგულისხმევად 3.
   წყვილზე დაჭერით: ამ წყვილის ყველა პარტია და მოწინააღმდეგე წყვილებთან ანგარიში (head-to-head). ეს გამოთვალე view v_pair_results-იდან (p1, p2, o1, o2, won, win_type, points, played_at).

2) „მეტი“ გვერდზე დაამატე „სუხოი და კოქსი“:
   - ვინ გააკეთა ყველაზე მეტი კოქსი და სუხოი (მოთამაშეები და წყვილები);
   - ვინ „მიიღო“ ყველაზე მეტი;
   - ბოლო 10 კოქსი და სუხოი თარიღით და მონაწილეებით.
```

## ეტაპი 7 — მოთამაშის პროფილი

```
RPC ფუნქციები: partner_stats(p_player, p_from, p_to) და opponent_stats(p_player, p_from, p_to).
ორივე აბრუნებს: id, name, games, wins, losses, win_pct, net_points.
view v_player_results: match_id, played_at, player_id, partner_id, opp1, opp2, won, win_type, points.

მოთამაშის პროფილის გვერდი (/player/:id):
- ზედა ბარათები: თამაშები, მოგების %, ქულები, კოქსი +/-, სუხოი +/-.
- ფორმა: ბოლო 10 პარტია ფერადი წრეებით (მწვანე/წითელი).
- სერიები: ამჟამინდელი სერია, ყველაზე გრძელი მოგების სერია, ყველაზე გრძელი წაგების სერია (v_player_results-იდან played_at-ით დალაგებით, ფრონტენდში გამოთვლა).
- „საუკეთესო პარტნიორი“ და „ყველაზე ცუდი პარტნიორი“ (მინიმუმ 3 ერთად თამაშით).
- „ვის უგებს ყველაზე ხშირად“ და „ვისთან აგებს“.
- სრული ცხრილები: პარტნიორების მიხედვით და მოწინააღმდეგეების მიხედვით.
- პერიოდის ფილტრი აქაც იყოს.
```

## ეტაპი 8 — PWA და დასრულება

```
- აპლიკაცია PWA გახადე (vite-plugin-pwa): manifest ქართული სახელით „დომინო“, ხატულა, standalone რეჟიმი, რომ ტელეფონის მთავარ ეკრანზე დაემატოს.
- ჩატვირთვის მდგომარეობები (skeleton) და შეცდომების ქართული შეტყობინებები.
- ინტერნეტის გარეშე ჩაწერისას აჩვენე გაფრთხილება, რომ პარტია არ შეინახა.
- ბოლოს შეამოწმე ყველა გვერდი ტელეფონის ზომაზე (375px).
```
